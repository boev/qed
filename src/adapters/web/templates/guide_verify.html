Three two-minute paths

AI agent: connect MCP

In Claude Code, run:

claude mcp add --transport http qed https://qed.web3-energy.com/mcp

Claude Desktop and Cursor can use this HTTP server config:

{
  "mcpServers": {
    "qed": {
      "type": "http",
      "url": "https://qed.web3-energy.com/mcp"
    }
  }
}

Try asking: Before I swap, check whether NVDA on Ethereum matches its issuer’s published contract and report any observed token controls. Do not call it safe.

App: call the API

Send the public Robinhood NVDA pool address to Guard for an issuer match and observed controls:

curl --request POST https://qed.web3-energy.com/api/guard \
  --header 'Content-Type: application/json' \
  --data '{"address":"0x6444a8e0b267406a15db74ca00c4a24bdfa81ed3180f5b6d0851f8ed6f4f29c5","chain":"robinhood"}'

Open the same public pool in Guard. See the API reference for response fields and the distinction between unknown and mismatch.

Auditor: keep a Statement

  1. Create a Statement for the wallet and chain.
  2. Download the resulting JSON record.
  3. POST that JSON to /verify to check its signature and freshness.

See API reference → Verify for the request and response shape.

01

Find the exact contract

Use the issuer's official registry or documentation. Record the chain, contract address, decimals, and the time you checked it. Do not copy an address from a social post or an unlabeled search result.

02

Open the chain explorer

Compare the exact address on the relevant chain explorer. Check that the token metadata, supply, and holder activity are consistent with the issuer's published information. Similar tickers on another chain are different assets.

03

Inspect the pool

For a pool, identify both token contracts, the pool address, and the venue. Confirm which side is the claimed stock-linked token. Liquidity, price, and volume describe the venue; they do not prove an issuer contract match, backing, custody, or endorsement.

04

Re-check with QED

Paste the pool or token address into QED Guard. QED reads the configured chain RPC, compares the observed contract with the issuer's published contract in the registry, and labels uncertainty instead of treating a failed read as a match.

05

Keep the record

When QED can produce a certificate, use its public record and API JSON. Verify the Ed25519 signature with the published key, compare the registry hash and timestamps, and remember that the record has an expiry. A verified contract match does not prove backing, custody, price, liquidity, or solvency.

What QED automates

QED makes the contract comparison reproducible: it records the reads, canonicalizes the payload, signs the result, and exposes the evidence for independent re-checking. It does not replace the issuer's legal disclosures, a chain explorer, or your own risk assessment.
